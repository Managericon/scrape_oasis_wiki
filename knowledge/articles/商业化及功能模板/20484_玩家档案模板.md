# 玩家档案模板

创建于 2026-10-08 06:19

玩家档案模板是绿洲编辑器提供的官方功能模板，提供了和平精英局内玩家名片/玩家档案的能力，展示他人头像、昵称、性别、段位，并支持加好友、私聊、举报、邀请组队、踢出队伍等操作。

> 模板本身不实现任何档案数据获取逻辑，只负责UI展示与交互，全部数据来自内核GamePart `PlayerProfileManager` 。该模板大部分功能在调试期间无效，需在真机测试环境检查效果

### 注册回调并注册监听

由于GamePart为异步加载，`ReceiveBeginPlay` 时组件通常还不可用，需轮询等待 `IsLoaded()` 。需在 `Script/Blueprint/UGCPlayerController.lua` 中添加以下逻辑：

```
function UGCPlayerController:ReceiveBeginPlay()
    UGCPlayerController.SuperClass.ReceiveBeginPlay(self)

    local profile_ui_ref = nil
    local retryCount = 0
    -- CreateLuaTimer 循环定时器不认 return false，用标志位防止重复注册监听
    local bRegistered = false

    UGCTimerUtility.CreateLuaTimer(1, function()
        if bRegistered then return end
        retryCount = retryCount + 1

        local pm = UGCGamePartSystem.PlayerProfileManager
        if not pm or not pm.IsLoaded or not pm.IsLoaded() then
            return
        end

        local PC = self
        local PlayerProfileComponent = UGCGamePartSystem.GetGamePartPlayerComponent(
            "PlayerProfileManager", PC, "PlayerProfileManager")
        if not PlayerProfileComponent or not UE.IsValid(PlayerProfileComponent) then
            return
        end
        if not PlayerProfileComponent.OnPlayerProfileOpen then
            return
        end

        PlayerProfileComponent.OnPlayerProfileOpen:Add(function(UID, IconURL, NickName, PlatformGender, bIsOnline)
            -- 注意字段名映射：回调的 IconURL/NickName/PlatformGender
            -- 对应 UGC_PlayerProfile_UIBP:SetData 的 PicUrl/Name/Sex
            local data = {
                UID = UID,
                PicUrl = IconURL,
                Name = NickName,
                Sex = PlatformGender,
                bIsOnline = bIsOnline,
            }

            if profile_ui_ref and UE.IsValid(profile_ui_ref) then
                profile_ui_ref:SetData(data)
                profile_ui_ref:AddToViewport(10101)
                profile_ui_ref:SetVisibility(ESlateVisibility.SelfHitTestInvisible)
                return
            end

            local Path = UGCGameSystem.GetUGCResourcesFullPath(
                'ExtendResource/PlayerProfileTemplate/OfficialPackage/Asset/PlayerProfile/ArtsUI/UGC_PlayerProfile_UIBP.UGC_PlayerProfile_UIBP_C')
            UGCWidgetManagerSystem.CreateWidgetAsync(Path, function(Widget)
                if not Widget then return end
                profile_ui_ref = Widget
                Widget:SetData(data)
                Widget:AddToViewport(10101)
                Widget:SetVisibility(ESlateVisibility.SelfHitTestInvisible)
            end)
        end)

        bRegistered = true
    end, true)
end
```

### 打开玩家档案窗口

> 该功能在调试期间无效，需在真机测试环境检查效果

开发者可调用 `PlayerProfileComponent:RequestPlayerProfile` 打开特定玩家档案窗口，示例代码如下：

```

function MainUI:Button_OnClicked()
	--- 获取玩家档案组件
	local PC = UGCGameSystem.GetLocalPlayerController()
	local PlayerProfileComponent = UGCGamePartSystem.GetGamePartPlayerComponent("PlayerProfileManager", PC, "PlayerProfileManager")
	if not PlayerProfileComponent or not UE.IsValid(PlayerProfileComponent) then
		return
	end
	--- 打开自身的玩家档案
	local TargetUID = UGCGameSystem.GetUIDByPlayerController(PC)
	PlayerProfileComponent:RequestPlayerProfile(TargetUID)
	return nil
end
```

### UI 挂载方式

挂载玩家档案UI需使用 `AddToViewport(10101)` 。原因是名片需要显示在聊天、社交等系统界面之上，10101 能确保UI在聊天层之上显示。

> 若你的玩法统一走挂点槽位管理 UI，可改为 UGCWidgetManagerSystem.AddToSlot，但需确认槽位层级高于聊天界面，否则名片会被遮挡。

## 注意事项

### 1\. 必须自行注册监听

玩家档案模板没有 `Cmpt` 组件层，开发者必须：

  1. 配置 GamePart 并手动挂载 `BP_PlayerProfile_PlayerComponent` 到 `PlayerController` 上，并勾选【组件复制】
  2. 在自己 `PlayerController` 的 `ReceiveBeginPlay` 中轮询等待 `PlayerProfileManager` 加载
  3. 手动 `OnPlayerProfileOpen:Add(...)` 注册回调
  4. 在回调中自己创建 UI、自己挂载、自己管理实例引用

* * *

### 2\. 组件手动挂载与复制缺一不可

只配置 `GP_PlayerProfileManager` 而没有在GamePart Config蓝图中把 `BP_PlayerProfile_PlayerComponent` 挂到 `PlayerController` 上，或忘记勾选 `Replicates` 时，都会导致组件不可用：即 `GetGamePartPlayerComponent` 返回nil，注册监听永远重试，点击头像毫无反应，且日志无明显报错。

排查时需优先确认以上两项，再去检查 GamePart 是否加载。

* * *

### 3\. 回调字段名与 UI SetData 字段名不一致（高频坑）

`OnPlayerProfileOpen` 给的是 `IconURL`、 `NickName`、 `PlatformGender`，而模板 `UGC_PlayerProfile_UIBP:SetData` 要的是 `PicUrl`、 `Name`、 `Sex`。

照抄官方示例的 `Show({UID=UID, IconURL=IconURL, ...})` 直接传给 `SetData`，三个字段全是 nil，**名片头像、昵称、性别全部空白** ，但日志不会报错，极难排查。务必显式做映射（见「注册回调并注册监听」部分的示例代码）。

* * *

### 4\. GamePart 异步加载，必须轮询等待（重要时序）

`ReceiveBeginPlay` 时 `PlayerProfileManager` 通常尚未加载完成，直接 `GetGamePartPlayerComponent` 会拿到 nil。必须轮询 `UGCGamePartSystem.PlayerProfileManager.IsLoaded()`。

**关键坑** ：`UGCTimerUtility.CreateLuaTimer` 的循环定时器**不认`return false`**，回调返回 false 不会停止定时器。示例代码用 `bRegistered` 标志位在注册成功后置 true 并 `return` 空转，这是正确做法，改造时**不要删掉这个标志位** ，否则会重复注册同一委托，导致一次点击弹出多次名片。

* * *

### 5\. 聊天头像入口是降级设计，不是 bug

开启 `bEnablePlayerProfileInChat` 后，聊天头像点击走你的 UI；**未加载`GP_PlayerProfileManager` 或未开启该开关时，聊天头像点击继续使用原有玩家名片流程**。

所以如果发现"聊天里点头像弹的是系统名片而不是我的 UI"，先查这两项，不要去改聊天逻辑——开关打开后内核会自动触发，开发者无需介入聊天模块。

* * *

### 6\. 必须用 CreateWidgetAsync 而非同步 LoadClass

对局中同步 `LoadClass` 会触发 `FlushAsyncLoading`（`Not_Allow_Flush`）导致回调被中断，UI 创建不出来。模板示例统一用 `UGCWidgetManagerSystem.CreateWidgetAsync`。

* * *

### 7\. 拦截点击自己

模板 UI 层不判断"是不是点自己"。组队模板的 `OpenPlayerProfile()` 已内置拦截（比对本地 UID），但自定义入口必须自己加这段判断，否则会给玩家弹出自己的名片。

* * *

### 8\. 性别与大厅隐私设置联动

`OnPlayerProfileOpen` 返回的 `PlatformGender` 是原始值，UI 内部会再调 `UGCPlayerStateSystem.GetPlayerPlatformGender(data.Sex, data.UID)` 二次处理：**玩家在大厅开启「隐藏性别」时该函数返回 0，UI 会折叠整个性别 Switcher** 。

自定义渲染性别时请沿用这个二次处理，不要直接用返回的原始值，否则会泄露玩家隐私设置。

* * *

### 9\. 段位信息未实现

`UGC_PlayerProfile_RankTitleInfo_UIBP` 是空壳，主界面 `SetData` 中段位逻辑为 TODO。需要展示真实段位时，需自行接入段位 GP 并补全该子控件。

* * *

### 10\. 踢出后的轮询刷新机制

调用 `KickMember` 后，本地队友列表不会立刻更新，此时重算按钮仍会显示"踢出"。模板启动 **0.1 秒轮询** （`PlayerProfile_KickRefresh`），直到目标从 `GetAllTeammatePlayerState` 中消失才刷新为"邀请"并停止轮询。

重构时**必须保留** 这个机制，否则踢人后按钮状态不变化。

* * *

### 11\. 队伍成员变化监听的作用

UI 在 `Construct` 中注册了 `UGCTeamSystem.OnTeamMemberLeaveDelegate` / `OnTeamMemberJoinDelegate`，用于被踢 / 他人加入时重算按钮显隐。**`Destruct` 中必须成对 `Remove`**，否则玩家反复开关名片会累积注册，导致一次成员变化触发 N 次刷新。

* * *

### 12\. 跨 DS 邀请的限制

`OnInviteClicked` 按好友关系分流：

目标 | 走接口 | 跨 DS
---|---|---
好友 | `UGCTeamSystem.InviteLobbyFriend` | 支持（内核自动判断同 DS / 跨 DS 投递）
非好友 | `UGCTeamSystem.InviteInGamePlayer` | **不支持，跨 DS 会失败**

* * *

### 13\. UI 复用而非重复创建

示例用 `profile_ui_ref` 缓存已创建的 Widget，再次打开时先 `SetData` 再重新 `AddToViewport`。这样避免重复创建实例、也避免旧实例泄漏。若自己实现销毁逻辑（如 `RemoveFromParent` 后置 nil），注意同步清空 `profile_ui_ref`。

* * *

### 14\. 蓝图软类路径属性为 Pass 模板残留

`UGC_PlayerProfile_UIBP` 蓝图上存在 `BuyAdvancedPassClassPath`、`PassPrizeClassPath`、`GetPopupUIClassPath` 等属性，以及导入的 `Pass` 相关资源，均为赛季手册模板的打包残留，**当前 Lua 逻辑完全没有使用** ，不影响功能，也无需配置。

* * *

### 15\. 扩展时的清理义务

`Destruct` 会清理全部按钮委托、队伍成员监听与踢人轮询定时器。若新增定时器或监听，**必须同步在此清理** ，否则切 DS / 反复开关后会泄漏。

## 常见问题解答（FAQ）

### Q1：点击头像完全没反应？

依次排查：① GamePart Config 蓝图中是否**手动挂载** `BP_PlayerProfile_PlayerComponent` 到 PC、是否**勾选 Replicates** （见注意事项第 2 条，最高频）；② `DA_GameModeGeneral` 的 `Active Game Part Configs` 是否添加了 `GP_PlayerProfileManager`；③ 日志是否出现 `OnPlayerProfileOpen 监听注册成功`；④ 是否调用了 `RequestPlayerProfile(UID)`；⑤ 是否点到了自己。

* * *

### Q2：名片弹出来了但头像、昵称、性别全是空的？

字段名没做映射。回调给的是 `IconURL`/`NickName`/`PlatformGender`，`SetData` 要的是 `PicUrl`/`Name`/`Sex`。见「注意事项」第 3 条。

* * *

### Q3：日志一直打印"轮询第 N 次"？

说明 `PlayerProfileManager.IsLoaded()` 一直返回 false，或 `GetGamePartPlayerComponent` 拿不到组件。检查 GamePart 是否启用、DataAsset 是否配到 `UGCGameState`、组件是否挂到 PC 上。超过 30 次会打印 `重试30次仍拿不到组件，放弃`。

* * *

### Q4：聊天里点头像弹的是系统名片，不是我的 UI？

未开启 `bEnablePlayerProfileInChat`，或未加载 `GP_PlayerProfileManager`。开启后内核自动触发回调，不需要改聊天逻辑。见「注意事项」第 5 条。

* * *

### Q5：一次点击弹出多次名片？

注册监听时删掉了 `bRegistered` 标志位，导致循环定时器每轮都 `Add` 一次委托。见「注意事项」第 4 条。

* * *

### Q6：可以不请求当前对局内的玩家吗？

可以。`RequestPlayerProfile` 的**目标玩家可以不在当前对局中** ，只要拿到 UID 即可（如好友列表、历史战绩）。

* * *

### Q7：性别图标不显示？

先确认返回性别非 0；若玩家在大厅开启「隐藏性别」，`GetPlayerPlatformGender` 会返回 0，UI 会主动折叠性别控件——这是符合隐私设计的正常表现，不是 bug。

* * *

### Q8：段位区域空白？

段位功能尚未实现，`UGC_PlayerProfile_RankTitleInfo_UIBP` 为空壳。见「注意事项」第 9 条。

* * *

### Q9：邀请/踢出按钮都不出现？

两个按钮共用 `WidgetSwitcher_0`，条件互斥。检查：① 玩法小队人数上限是否 ≥ 2（`GetTeamPlayersNumber()`）；② 目标是否在线；③ 自己是否队长、目标是否队友。另注意 `GetTeamPlayersNumber()` 在部分模式配置下返回值可能与编辑器设置不符，建议实测校验。

* * *

### Q10：踢出队友后按钮还是显示"踢出"？

0.1 秒轮询等待数据源落地，正常情况下会很快自动变"邀请"。若长期不变，检查 `PlayerProfile_KickRefresh` 定时器是否被误清理，日志关键字 `数据源已落地，刷新按钮`。

* * *

### Q11：加好友按钮点了没反应？

检查 `UGCGameSystem.AddFriend` 是否存在，以及 UID 是否有效（`_playerData.UID` 需 > 0）。已是好友时该按钮本就隐藏。

* * *

### Q12：私聊要不要先判断好友关系？

不需要。`UGCMessageSystem.OpenPrivateChat(UID)` 对好友和非好友**统一打开临时会话** ，直接传 UID 即可。

* * *

### Q13：举报要不要先查档案数据？

不需要。`UGCGameSystem.OpenComplaintUI(UID)` 直接传 UID 即可打开指定玩家的举报界面。

* * *

### Q14：名片被聊天界面遮挡？

层级问题，模板用 `AddToViewport(10101)`。若你改成挂点槽位，需确认槽位层级高于聊天 UI。

## 附：日志关键字速查

组件日志 TAG 为 `[PlayerProfile] `。

关键字 | 含义
---|---
`PC ReceiveBeginPlay 开始` | PC 启动，开始轮询
`轮询第N次` | 等待 GamePart 加载中
`IsLoaded=true` | GamePart 已加载
`OnPlayerProfileOpen 监听注册成功! 共重试N次` | 注册成功，N 为重试次数
`!!! OnPlayerProfileOpen 委托不存在` | 组件上没有该委托，版本不匹配
`!!! 重试30次仍拿不到组件，放弃` | 组件未挂载 / GamePart 未启用 / 配置错误
`>>> OnPlayerProfileOpen 回调触发!` | 档案数据就绪，准备弹 UI
`复用已有UI` | 命中缓存实例，走 SetData 复用
`创建新UI` | 首次创建，走 CreateWidgetAsync
`!!! CreateWidgetAsync 失败` | UI 路径错误或资源未导入
`UI创建成功!` | 名片已挂载
`SetData() UID=x Name=y` | 数据下发。**Name 为空说明字段名未映射**
`OnKickClicked: GetPlayerKeyByUID 返回 nil，无法踢出` | UID 换 PlayerKey 失败，踢人中止
`_StartKickRefreshPoll 数据源已落地，刷新按钮` | 踢人后队友列表已更新
`Construct 已注册队伍成员变化监听(刷新名片按钮)` | 队伍监听注册成功
