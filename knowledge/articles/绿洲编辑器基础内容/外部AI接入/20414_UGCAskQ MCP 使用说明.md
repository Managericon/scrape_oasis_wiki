# UGCAskQ MCP 使用说明

创建于 2026-07-10 07:09 最后修改于 2026-10-23 11:09

> 本文档帮助开发者快速上手 UGCAskQ MCP，了解如何将 AI 助手接入绿洲启元编辑器，并高效完成玩法内容的制作。

> **⚠️ 重要提示：实验性功能**
>
> UGCAskQ MCP 目前处于**早期实验阶段** ，功能仍在持续迭代中，可能存在不稳定的情况。在使用前，请务必注意以下事项：
>
>   * **备份工程** ：每次使用 MCP 前，请先保存并备份当前工程文件，避免因 AI 误操作导致数据丢失或损坏
>   * **逐步验证** ：建议每次只让 AI 执行一小步操作，确认效果无误后再继续，避免一次性执行大量不可逆操作
>   * **结果不一定准确** ：AI 生成的配置参数、节点结构等可能不完全符合预期，使用后请人工检查关键内容
>   * **功能范围有限** ：并非所有编辑器模块都支持 MCP 操作，具体支持范围见下文"支持的编辑器功能"章节
>

* * *

## 概述

UGCAskQ MCP（Model Context Protocol）是绿洲启元编辑器的 AI 协作接口，允许 Claude、Cursor、WorkBuddy、CodeBuddy 等 AI 助手直接读取和操作编辑器中的各类内容，让开发者可以通过自然语言来完成复杂的编辑器操作。AskQ 在 UGCEditor 内以本机 SSE 服务暴露编辑器能力。AI 客户端连上后，按「先读后写」的流程改工程数据：先调用只读接口确认当前值，再下达修改指令。

连接后，AI 助手能够感知当前编辑器的状态（当前选中了哪些对象、场景里有什么、哪个技能配置了什么），并代替开发者执行操作，例如批量添加 Actor、配置技能属性、生成行为树节点等。

> **推荐做法：** 使用更强的大语言模型，可以获得更准确、更流畅的操作体验。

## 快速接入

### 第一步：打开 MCP Server

在编辑器顶部菜单栏依次点击 **窗口 → 开发者工具 → MCP Server** ，打开 MCP Server 控制面板。

面板顶部会显示当前服务状态。若显示 **Running（Port: 33444）** 等字样（绿色），说明服务已正常启动，可以直接进行第二步。

若服务未启动，点击面板内的 **Start Server** 按钮手动启动。

> **提示：** 如果端口连接失败，可以在面板中修改 Port 值后重新点击 Start Server。

### 第二步：在 AI 客户端中配置 MCP

#### 自动配置

在你的 AI 客户端里运行以下提示词：

```
请帮我在当前这个 AI 客户端里配置 AskQ（UGC 编辑器）MCP，要求：
1. 先识别我现在用的是哪个客户端（例如 WorkBuddy、CodeBuddy、Claude Desktop、Cursor），以及它存 MCP 配置的位置与格式。不要假设一定是某一个产品。
2. 合并写入，不要删掉已有其它 MCP 服务器。
3. 增加或覆盖名为 UGC-AskQ 的 SSE 条目，地址：http://127.0.0.1:12463/sse
若该客户端字段名不是 url（例如有的用 serverUrl / type:sse），按该客户端官方写法转换，语义不变。
4. 配完告诉我：识别到的客户端、改了哪个文件、完整写入片段、是否需要我重启 MCP / 重载窗口。
5. 如果本机 AskQ 端口不是 12463，或你不确定配置路径，先问我再写。
```

#### 手动配置

以 Claude 为例，在项目根目录（或工作区根目录）创建 `.mcp.json` 文件，内容如下：

```
{
  "mcpServers": {
    "ugcaskq": {
      "type": "sse",
      "url": "http://127.0.0.1:33444/sse"
    }
  }
}
```

将 `33444` 替换为 MCP Server 控制面板中显示的实际端口号。保存后重新启动 AI 客户端，即可连接到编辑器。

> **Cursor / VS Code 用户：** 在对应客户端的 MCP 设置中，以 SSE 类型添加上述地址即可。

### 第三步：验证连接

连接成功后，向 AI 助手发送一条简单问题来确认：

  * _“当前场景里有哪些 Actor？”_
  * _“你现在能在编辑器里做哪些操作？”_

AI 助手能够正确回答，说明连接已生效。

## MCP Server 控制面板说明

配置项 | 说明 | 推荐设置
---|---|---
**Port** | 服务监听端口，默认 33444 | 默认即可，冲突时修改
**Enforce Level** | PRV 安全策略级别 | `Observe`（推荐，警告但不阻断）
**Enable MCP Call Logging** | 是否记录每日调用日志 | 开启
**Idle Boundary (sec)** | 空闲超时阈值，超过后开启新的任务段 | 90 秒（0 表示关闭）

点击 **Open Log Folder** 可以打开日志目录，查看当天所有 MCP 调用记录（`Saved/log/MCP_YYYYMMDD.log`）。

## 支持的编辑器功能

MCP 当前已覆盖绿洲启元编辑器中以下模块的操作能力：

### 场景与 Actor 管理

在世界场景中放置和管理 Actor 是 MCP 最基础的能力之一，支持：

  * 在场景中**创建和放置 Actor** ，指定位置、旋转和缩放
  * **查询和修改** Actor 的属性（Transform、标签、父子关系）
  * **批量操作** ，例如一次性在指定区域放置多个同类 Actor

**使用示例：**

> _“在坐标 (0, 0, 100) 处放置一个 BP_Rock 资产，并将其缩放设置为 2”_
>  _“选中场景中所有名为 ‘Barrel’ 的 Actor，统一移动到 Z=50 的高度”_

* * *

### 技能编辑器

支持通过 AI 完成技能的创建和属性配置，适合快速搭建技能原型：

  * **创建新技能** ，指定技能类型和基本属性
  * **读取现有技能** 的配置内容，用于核查或二次修改
  * 配置技能的**基础数值参数** （如冷却时间、消耗值等）

**使用示例：**

> _“帮我创建一个近战技能，冷却时间 3 秒，消耗能量 20”_
>  _“读取’闪现’技能的当前配置，列出所有参数”_

* * *

### 物品编辑器

支持对玩法物品进行创建和配置：

  * **创建物品** ，设置物品类型、名称、图标等基础信息
  * **查询物品** 列表，按类别筛选
  * 修改物品的**数值属性**

**使用示例：**

> _“创建一个消耗品类型的物品，名称为’急救包’，描述为’恢复 50 点生命值’”_

* * *

### 行为树

AI 可以辅助搭建怪物和 NPC 的行为逻辑，支持：

  * **创建和读取** 行为树资产
  * 添加和配置行为树**节点** （Selector、Sequence、Task 等）
  * 为节点**挂载 Lua 脚本** ，扩展自定义行为逻辑

**使用示例：**

> _“帮我给 Boss 行为树添加一个巡逻节点，当血量低于 30% 时切换到逃跑状态”_
>  _“查看当前行为树的节点结构”_

* * *

### 蓝图编辑器

支持对蓝图资产的基础操作：

  * **创建** 新蓝图资产，指定父类
  * **查询** 蓝图变量和函数列表
  * 添加**变量** （Bool、Int、Float、Vector 等类型）
  * 向**黑板** 中添加键值

**使用示例：**

> _“在角色蓝图中添加一个名为 ‘IsAttacking’ 的 Bool 变量”_
>  _“查看当前蓝图有哪些公开变量”_

* * *

### UI 编辑器（UMG）

支持 AI 辅助进行 UI 控件的创建和布局：

  * **创建 UMG 蓝图** 资产
  * 在 Widget 中**添加控件** （Button、Text、Image、ProgressBar 等）
  * 设置控件的**位置、大小和锚点**
  * 配置控件的**文本内容和颜色**

**使用示例：**

> _“创建一个血量条 Widget，包含一个 ProgressBar 和一个显示数字的 Text 控件”_
>  _“把确认按钮的背景色改成蓝色，文字改为’开始游戏’”_

* * *

### 数据表（配置表）

支持对游戏内配置数据进行读写：

  * **读取** 数据表的行数据
  * **添加和修改** 数据行
  * 支持常见配置场景，如物品表、技能表、掉落表

**使用示例：**

> _“在物品配置表中添加一行，ID 为 1001，类型为武器，攻击力 50”_
>  _“查看技能配置表中 ID 为 2001 的那一行”_

* * *

### 实体编辑器

支持对游戏内实体（怪物、NPC 等）进行属性配置：

  * **查询** 实体的当前配置
  * **修改** 实体的属性（生命值、移速、攻击距离等基础参数）
  * 读取实体挂载的**组件信息**

**使用示例：**

> _“把精英小怪的生命值改为 800，移速提高 20%”_

* * *

### 资产查找与视窗控制

  * **搜索资产** ：按名称或类型在内容浏览器中查找资产路径
  * **视窗操作** ：控制编辑器摄像机的位置和朝向，聚焦到指定 Actor

**使用示例：**

> _“帮我找到名称包含 ‘Weapon’ 的所有静态网格资产”_
>  _“把视角移动到场景原点，俯视角度”_

* * *

## 修常见编辑器报错

把弹窗原文丢给 AI，比只说 “好像有问题” 有效得多。下面是绿洲启元编辑器里高频出现的几类校验弹窗，可以直接复制粘贴给 AI：

  * ItemID[1001] Icon 不能为空
  * ItemName 超过 15 字
  * ItemDesc 超过 60 字
  * ItemID 不在允许范围
  * 虚拟物品映射 ID 不存在
  * Shop ProductId 非法

> ⚠️ AI 改完后，在编辑器里再点一次校验；**最终以编辑器与进游戏为准** ，AI 改完不代表真的过了平台校验。

## 易踩坑场景

你想让 AI 做的事 | 现状 | 怎么办
---|---|---
一句话 “做完整套怪物系统（模型+AI+掉落+UI）” | 链路太长，中间易漏 | 拆开：先血量，再掉落，再刷怪
同一批表靠对话改上百次 | 上下文膨胀，又慢又贵 | 拆成几次短对话，或先改一小批
只说 “帮我优化一下手感” | 目标不具体 | 说清字段与目标值，如 “开火间隔从 0.1 改到 0.15”

> **说清楚「改谁、改哪个字段、改成多少」，成功率最高。**

## 推荐使用方式

场景 | 你对 AI 说（示例） | AI 大致做什么
---|---|---
改数值/属性 | “把哥布林血量改成 500，攻击改成 30” | 定位怪物配置，改字段并保存

## 常见问题

**Q: AI 连接后说"找不到服务器"怎么办？**
A: 确认 MCP Server 控制面板显示为 Running 状态；检查 `.mcp.json` 中的端口号与面板一致；重启 AI 客户端后重试。

**Q: 操作后编辑器没有反应？**
A: 部分操作完成后需要在编辑器中手动刷新对应面板。例如蓝图变量添加后，需要重新打开蓝图编辑器才能看到新变量。

**Q: 如何让 AI 了解当前场景的状态？**
A: 直接询问 AI "当前场景里有什么？“或"我现在选中了什么？”，AI 会主动通过 MCP 查询编辑器状态后回答。

**Q: 调用记录在哪里查看？**
A: 点击 MCP Server 面板中的 **Open Log Folder** ，可以看到按天归档的调用日志（`MCP_YYYYMMDD.log`），用于排查异常操作。

**Q: 能不能一边在编辑器里操作，一边让 AI 辅助？**
A: 可以。AI 会感知到你当前选中的 Actor 或打开的编辑器，可以基于你的操作上下文提供针对性的帮助。

## 推荐使用节奏

  1. **连上先摸底** ：让 AI 报告当前工程里有哪些对象、目标现在叫什么，再下达修改指令。
  2. **一次改一件事** ：先 “血量 500”，确认保存后再改攻击；避免一句话让 AI 同时改 5 个字段。
  3. **改完自己点校验或进 PIE** ：AI 改完不代表过了平台校验，最终以编辑器校验与进游戏为准。

* * *

## 注意事项

  * MCP 仅接受**本机** 连接（默认 127.0.0.1），不支持远程访问；不要把端口暴露到公网。
  * AI 操作直接作用于工程，**操作前请先保存并备份工程** ，避免误操作导致数据丢失。
  * 复杂的多步骤操作（完整关卡搭建）请分阶段让 AI 执行，每阶段确认效果后再继续。
  * 部分编辑器（**特效编辑器、音频编辑器** 等）当前暂无 MCP 接口，操作这些模块时仍需在编辑器内手动完成。
  * 实验性功能：MCP 仍处于早期迭代，可能不稳定；建议每次只让 AI 执行一小步、逐步验证。
